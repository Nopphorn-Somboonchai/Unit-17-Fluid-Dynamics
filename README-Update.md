## 📖 Project Overview & Learning Objectives

โปรเจกต์สื่อการสอนแบบโต้ตอบ (Interactive Web Application) ออกแบบมาเพื่อช่วยให้นักเรียนระดับชั้นมัธยมศึกษาปีที่ 6 เข้าใจกลศาสตร์การเคลื่อนที่ของของไหล (พลศาสตร์ของของไหล) ได้แก่ สมบัติของของไหลอุดมคติ (*Ideal Fluid*), อัตราการไหล ($Q = Av$), สมการความต่อเนื่อง ($A_1 v_1 = A_2 v_2$), สมการแบร์นูลลี ($P + \frac{1}{2}\rho v^2 + \rho g h = \text{const}$) ตลอดจนการประยุกต์ใช้งานในชีวิตประจำวัน ผ่านการจำลองภาพเสมือนจริง (Virtual Simulation) การฝึกทำโจทย์สุ่มแปรผันตามเลขที่ และระบบสอบเก็บคะแนนแบบจับเวลา

### จุดประสงค์การเรียนรู้ (Learning Objectives)
1. **เชิงทฤษฎี**: อธิบายสมบัติ 4 ประการของของไหลอุดมคติ และหลักการทำงานของปรากฏการณ์ทางพลศาสตร์ของของไหล เช่น กฎของตอร์รีเชลลี และแรงยกปีกเครื่องบิน
2. **เชิงคำนวณ**: คำนวณหาค่าอัตราการไหล ($Q$), อัตราเร็ว ($v$), พื้นที่หน้าตัดท่อ ($A$), และความดันของของไหล ($P$) โดยใช้สมการความต่อเนื่องและสมการแบร์นูลลีได้อย่างถูกต้อง
3. **เชิงปฏิบัติการ**: วิเคราะห์พฤติกรรมสายกระแส (*Streamlines*) ความเค้นความดัน และการเปลี่ยนผ่านพลังงานในระบบท่อผ่านเครื่องมือจำลองภาพเสมือนจริง (Virtual Simulator)

## 🎯 Design Philosophy

แอปพลิเคชันในระบบนิเวศนี้สร้างขึ้นโดยยึดหลักการออกแบบ 7 ประการ เพื่อให้การเรียนรู้วิทยาศาสตร์มีความเที่ยงตรงและยั่งยืน:

* **Learn by Interaction**: การเปลี่ยนผ่านจากความเข้าใจเชิงทฤษฎีไปสู่การมองเห็นภาพจริง เกิดขึ้นได้ดีที่สุดเมื่อผู้เรียนสามารถปรับเปลี่ยนตัวแปรทางฟิสิกส์และสังเกตผลลัพธ์ได้ทันทีแบบเรียลไทม์
* **Physics First**: ความถูกต้องแม่นยำของแบบจำลองทางคณิตศาสตร์และสมการฟิสิกส์ ต้องถูกนำมาพิจารณาก่อนความซับซ้อนของกราฟิกหรือเอฟเฟกต์การแสดงผล (Focus on conceptual understanding over visual complexity)
* **Reusable Architecture**: การออกแบบโครงสร้างและมอดูลต้องรองรับการนำรูปแบบไปใช้ซ้ำในบทเรียนอื่นๆ โดยไม่จำเป็นต้องเขียนสถาปัตยกรรมใหม่ทั้งหมด
* **Educational Clarity**: โครงสร้างโค้ดและการออกแบบ UI ต้องสะท้อนความหมายทางฟิสิกส์อย่างตรงไปตรงมา เพื่อให้ทั้งผู้พัฒนาและครูผู้สอนสามารถอ่านและทำความเข้าใจตรรกะได้ง่าย
* **Modular Design**: แยกแยะส่วนประกอบของระบบออกจากกันอย่างเด็ดขาด ป้องกันไม่ให้การเปลี่ยนแปลงจุดใดจุดหนึ่งกระทบกับระบบทั้งหมด
* **Maintainability**: ลดความซับซ้อนที่ไม่จำเป็น เพื่อให้แอปพลิเคชันสามารถดูแลรักษาในระยะยาวได้ง่าย แม้พัฒนาด้วยทีมงานขนาดเล็ก
* **Extensibility**: สามารถเพิ่มฟีเจอร์จำลองใหม่ๆ หรือชุดโจทย์คำนวณเพิ่มเติมได้โดยไม่ต้องรื้อระบบเดิม

## 🏗️ System Architecture

ระบบถูกออกแบบโดยแบ่งลำดับชั้นความรับผิดชอบ (Layered Architecture) เพื่อแยกส่วนประมวลผลทางฟิสิกส์ออกจากส่วนแสดงผลและส่วนปฏิสัมพันธ์กับผู้ใช้:

```
[ User / Student ]
        │
        ▼
   [ UI Layer ]               (DOM Events, Sliders, Form Controls, Buttons)
        │
        ▼
[ Simulator Layer ]           (Topic Orchestrator & State Management)
        │
        ▼
 [ Physics Engine ]           (Fluid Equations: Continuity & Bernoulli Solvers)
        │
        ▼
 [ Domain Models ]            (Fluid Properties, Pipe Geometry, Streamline Data)
        │
        ▼
  [ Renderer Layer ]          (Canvas 2D Rendering Engine & Streamline Vector Plotter)
        │
        ▼
   [ HTML5 Canvas ]           (Visual Output)
```

### หน้าที่ความรับผิดชอบของแต่ละ Layer:

1. **UI Layer**: รับอินพุตจากผู้ใช้ (เช่น การปรับขนาดท่อ $A_1, A_2$, การเลื่อนระดับความสูง $h$, การกรอกคำตอบ) และส่งต่อ event ไปยัง Simulator
2. **Simulator Layer**: ทำหน้าที่เป็น Orchestrator ควบคุมสถานะของแบบจำลอง (State Management) เชื่อมโยงข้อมูลระหว่าง UI, Engine และ Renderer
3. **Physics Engine**: คำนวณค่าทางฟิสิกส์ล้วนๆ โดยปราศจากส่วนการแสดงผล (Pure Functions) เช่น คำนวณอัตราการไหล $Q$, อัตราเร็ว $v$, ความดัน $P$ และแรงยก
4. **Domain Models**: จัดเก็บโครงสร้างข้อมูลของวัตถุและคุณสมบัติทางกายภาพ (เช่น ความหนาแน่นของของไหล $\rho$, ขนาดท่อ, ความสูง, พิกัดรูรั่ว)
5. **Renderer Layer**: รับค่าสถานะจาก Physics Engine/Models มาวาดเป็นภาพแอนิเมชัน 2D เวกเตอร์การไหล (*Streamlines*) และตัววัดความดันลงบน HTML5 Canvas
6. **HTML5 Canvas**: พื้นผิวการแสดงผลปลายทางที่แสดงผลลัพธ์เชิงทัศนวิสัยแก่ผู้ใช้

## 🧩 Separation of Concerns

เพื่อความโปร่งใสของโค้ดและการทดสอบที่ง่าย ระบบแยกหน้าที่ความรับผิดชอบ (Separation of Concerns) ตามโดเมนดังนี้:

* **Physics Calculations**: รับผิดชอบเฉพาะสมการทางคณิตศาสตร์ ตัวแปรทางฟิสิกส์ ( Continuity & Bernoulli equations) และการแปลงหน่วย ปราศจากตรรกะของ DOM หรือ Canvas
* **Rendering**: รับผิดชอบเรื่องพิกัดเวกเตอร์ การวาดเส้นสายกระแส (*Streamlines*) การลงสี ความเร็วแอนิเมชัน และการเคลียร์เฟรม Canvas โดยไม่มีตรรกะการคำนวณฟิสิกส์ซ้ำซ้อน
* **User Interface**: รับผิดชอบการผูก Event Listener, การอัปเดตข้อความบนหน้าจอ, แถบควบคุม Slider และการเปลี่ยนสลับแท็บ
* **Quiz Logic**: รับผิดชอบอัลกอริทึมการสุ่มตัวแปร (RNG), การประมวลผลคำตอบตามเลขที่ผู้เรียน ($R$), การตรวจคะแนน และการจัดรูปแบบข้อความเฉลย
* **Learning Content**: จัดเก็บข้อมูลเชิงทฤษฎี ข้อความอธิบาย และการเรนเดอร์สมการ $\LaTeX$ ผ่าน KaTeX
* **Simulation State**: ทำหน้าที่เป็น Single Source of Truth เก็บค่าสถานะปัจจุบันของตัวแปร เช่น อัตราการไหล ($Q$), ความเร็ว ($v_1, v_2$), ความดัน ($P_1, P_2$)

## 🔄 Simulator Lifecycle

แบบจำลองฟิสิกส์ (Simulator) ทุกตัวในระบบนิเวศนี้จะดำเนินตามวงจรการทำงานมาตรฐาน (Standard Lifecycle) เดียวกัน ดังแสดงในแผนภาพด้านล่าง:

```
    ┌─────────────────────────┐
    │     1. Initialize       │  (สร้าง Canvas Context & โหลดโมเดลท่อ/ของไหลตั้งต้น)
    └────────────┬────────────┘
                 │
                 ▼
    ┌─────────────────────────┐
    │   2. Load Parameters    │  (อ่านค่าจาก UI Sliders: A1, A2, h1, h2 หรือ preset ของไหล)
    └────────────┬────────────┘
                 │
                 ▼
    ┌─────────────────────────┐
    │   3. Calculate Physics  │  (ประมวลผล Q, v2, P2, Force ผ่าน Physics Engine)
    └────────────┬────────────┘
                 │
                 ▼
    ┌─────────────────────────┐
    │ 4. Update Simulation    │  (อัปเดตตำแหน่งอนุภาค และความเร็วเส้นสายกระแส Streamlines)
    └────────────┬────────────┘
                 │
                 ▼
    ┌─────────────────────────┐
    │     5. Render Scene     │  (วาดท่อ, อนุภาคของไหล, เกจวัดความดัน ลง Canvas)
    └────────────┬────────────┘
                 │
                 ▼
    ┌─────────────────────────┐
    │  6. Wait Interaction    │  (รอการปรับค่า Slider / เปลี่ยนจุดวัดความดัน)
    └────────────┬────────────┘
```

## ✨ Features & Interactive Modules

### 1. 📖 ระบบทบทวนบทเรียนและเครื่องมือจำลอง (Interactive Review & Physics Simulators)

* 🌊 **Simulator 1: การไหลของของไหลอุดมคติและสมการความต่อเนื่อง**
  * จำลองการไหลของของไหลผ่านท่อที่มีการเปลี่ยนแปลงพื้นที่หน้าตัด ($A_1, A_2$) และวัดอัตราเร็ว ($v_1, v_2$)
  * แสดงการคำนวณอัตราการไหลคงตัว ($Q = A_1 v_1 = A_2 v_2$) และแสดงเส้นสายกระแส (*Streamlines*) แบบเรียลไทม์
* ⚖️ **Simulator 2: สมการแบร์นูลลีและการเปลี่ยนแปลงความดัน**
  * จำลองการไหลของของไหลในท่อที่มีระดับความสูงต่างกัน ($h_1, h_2$) และพื้นที่หน้าตัดต่างกัน
  * คำนวณและแสดงผลความดัน ($P$), พลังงานจลน์ต่อหนึ่งหน่วยปริมาตร ($\frac{1}{2}\rho v^2$) และพลังงานศักย์โน้มถ่วงต่อหนึ่งหน่วยปริมาตร ($\rho g h$) ณ จุดต่าง ๆ
* ✈️ **Simulator 3: การประยุกต์ใช้พลศาสตร์ของของไหล**
  * จำลองอัตราเร็วของของไหลที่ออกจากรูด้านข้างภาชนะตาม **กฎของตอร์รีเชลลี** ($v = \sqrt{2gh}$)
  * จำลอง **แรงยกปีกเครื่องบิน (Airplane Wing Lift)** และหลักการทำงานของ **เครื่องพ่นละอองน้ำ**

### 2. 🧠 ระบบตะลุยโจทย์เฉพาะตัว (Roll-Number-Based Practice System)

* **โหมดการเรียนรู้**: เลือกได้ระหว่าง *โจทย์ตัวเลขคงที่ (ตามคู่มือ สสวท.)* และ *โจทย์สุ่มตัวเลข (RNG)*
* **หัวข้อคลังข้อสอบย่อย**:
  * `17.4.1` **ของไหลอุดมคติและอัตราการไหล**: สมบัติ 4 ประการของของไหลอุดมคติ และคำนวณอัตราการไหล $Q = \frac{\Delta V}{\Delta t} = A v$
  * `17.4.2` **สมการความต่อเนื่อง**: คำนวณหาอัตราเร็วหรือพื้นที่หน้าตัดท่อเมื่อของไหลไหลผ่าน $A_1 v_1 = A_2 v_2$
  * `17.4.3` **สมการแบร์นูลลีและการประยุกต์**: คำนวณความดัน อัตราเร็ว และความสูง $P_1 + \frac{1}{2}\rho v_1^2 + \rho g y_1 = P_2 + \frac{1}{2}\rho v_2^2 + \rho g y_2$ รวมถึงกฎของตอร์รีเชลลี ($v = \sqrt{2gh}$) และแรงยกปีกเครื่องบิน
* **ระบบเฉลยละเอียด**: แสดงผลการตรวจคำตอบทันทีพร้อมวิธีทำคำนวณสูตรฟิสิกส์ทีละขั้นตอนอย่างละเอียดในรูปแบบสัญลักษณ์คณิตศาสตร์ $\LaTeX$ ผ่าน KaTeX

## ⚙️ Dynamic Quiz System Rules

ระบบข้อสอบถูกออกแบบให้เป็น **Non-Deterministic Dynamic System** โดยผูกค่าตัวแปรในโจทย์เข้ากับ **"เลขที่ของนักเรียน (Roll Number: $R$)"** เพื่อให้มั่นใจว่านักเรียนแต่ละคนจะได้รับพารามิเตอร์โจทย์และคำตอบที่ไม่ซ้ำกัน

### 📌 สถาปัตยกรรมและลอจิกการทำงาน:
1. **Dynamic Parameter Generation**: ระบบจะดึงเลขที่ของนักเรียน ($R \in [1, 40]$) มาคำนวณร่วมกับฐานตัวแปรที่ถูกสุ่มขึ้นมาแบบอิสระ (*Non-deterministic Random*) เพื่อสร้างค่าพารามิเตอร์ชุดใหม่สำหรับโจทย์แต่ละข้อ
2. **On-the-fly Validation**: การประเมินคำตอบและเฉลยวิธีทำจะคำนวณแบบสดๆ (*On-the-fly*) จากเลขที่ $R$ ของผู้เข้าสอบจริง โดยไม่ใช้ค่าคงที่แบบสแตติก (*No Static Hardcoded Answers*)
3. **Safety Constraints**: สมการเบื้องหลังได้รับการกำหนดขอบเขตค่าต่ำสุด-สูงสุดไว้อย่างรัดกุม ป้องกันไม่ให้การคำนวณร่วมกับเลขที่ $R$ เกิดค่าที่ติดลบหรือผิดหลักการทางฟิสิกส์

## 🛠️ Development Principles

ผู้พัฒนาที่ต้องการสร้าง Simulator หรือ Repository ใหม่ในระบบนิเวศนี้ ควรปฏิบัติตามหลักการต่อไปนี้อย่างเคร่งครัด:

1. **Keep Physics Independent from Rendering**: ห้ามเขียนสูตรคำนวณทางฟิสิกส์ปะปนในฟังก์ชันวาด Canvas หรือ Event Listener
2. **Avoid Duplicated Formulas**: ศูนย์รวมสูตรและสมการฟิสิกส์ต้องถูกจัดการผ่าน Physics Engine หรือ Helper Module เพียงจุดเดียว
3. **Separate UI from Simulation Logic**: ส่วนติดต่อผู้ใช้ต้องมีหน้าที่เพียงส่งผ่าน Parameter และแสดงผลลัพธ์ ไม่ตัดสินตรรกะการจำลอง
4. **Keep Reusable Modules**: ออกแบบโค้ดในลักษณะโมดูลที่สามารถคัดลอกหรือ Import ไปใช้ในหัวข้อฟิสิกส์อื่นได้สะดวก
5. **Be Easy to Test**: ฟังก์ชันประมวลผลฟิสิกส์ต้องรับอินพุตและคืนค่าเอาต์พุตอย่างตรงไปตรงมา (Pure Functions) เพื่อรองรับ Unit Testing
6. **Be Easy to Extend**: เพิ่มชนิดของของไหล พารามิเตอร์ความดัน หรือรูปทรงท่อใหม่ได้โดยการปรับแก้เพียงไฟล์ Model/Config
